## Nguyên tắc BẮT BUỘC (đọc lại trước mỗi lệnh)
1. **UI-first tuyệt đối**: mọi thao tác của end-user là nút bấm trên giao diện Streamlit. KHÔNG bao giờ yêu cầu user sửa file, gõ lệnh, hay chỉnh config tay.
2. **KHÔNG tự cải tiến**: chỉ làm đúng yêu cầu, không tự thêm tính năng/đổi kiến trúc khi chưa được yêu cầu.
3. **CẤM sidebar**: không đặt bất kỳ setting nào trong sidebar (yêu cầu user 2026-07-23, áp dụng mọi app). Mọi tham số là ô **nhập số trực tiếp** (`st.number_input`) nằm ngay trong tab dùng nó; min/max chỉ đặt theo giới hạn kỹ thuật thật của API, không tự đặt trần thấp.
4. Tool chạy **local** — 2 tab check thủ công không phụ thuộc API trả phí. Tab phân tích API là adapter tách rời, key nhập trên UI, lưu `config.json` local. **Ngoại lệ duy nhất** (user yêu cầu 2026-07-25): mục "🔎 Tìm trang gốc trỏ 301" trong tab 2 dùng API (đọc `config.json` đã lưu ở tab 3), chỉ tốn phí khi user bấm nút đó — phần trace thủ công phía trên vẫn API-free.
5. Tab API mặc định **chỉ tier 1**; giới hạn backlink do user tự nhập (trần UI 1.000.000). Phân trang tự động trong adapter:
   - SE Ranking: **luôn dùng `/raw`** cho mọi limit (100k/lượt, cursor `next`) — theo docs, `/raw` là endpoint "complete backlink retrieval", còn `/all` chỉ là view lọc/sắp xếp có thể trả ÍT hơn thực tế (nguyên nhân bug "lấy được rất ít" user báo 2026-07-24, fix 2026-07-25); `/raw` lỗi 40x mới fallback `/all` (cap min(limit, 10k)) + ghi `provider.notes` (UI hiện thành warning). `/anchors`, `/refdomains` trần cứng 10.000 — adapter tự cap.
   - DataForSEO: vòng lặp `offset` từng 1.000 dòng đến khi đủ limit hoặc API trả thiếu (hết dữ liệu).

## Kiến trúc
- `app.py` — UI Streamlit, **4 tab** (Check Backlink / Check Redirect / Phân tích API / Lịch sử 24h):
  - Tab 1 `check_backlink(url, target)` — fetch trang, parse `<a href>`, so khớp domain đích (kể cả subdomain, bỏ www), trả về: còn link/mất link, anchor text, dofollow/nofollow, meta robots noindex.
  - Tab 2 `check_redirect(url, ua_pairs, history_sources)` — trace thủ công từng hop (`allow_redirects=False`), tối đa 10 bước, chuỗi status, URL cuối, vòng lặp. LUÔN gọi `detect_hidden_redirect()` trên HTML trang cuối (meta refresh + regex JS `location=`). **Đa nguồn, user tự chọn** (memory multi-source-api): `ua_probe(url, ua_pairs)` soi cloaking bằng CÁC User-Agent user chọn từ `UA_PRESETS` (multiselect, mặc định `UA_DEFAULT`) + UA tự nhập — ≥2 mới so; `redirect_history(url, sources)` tra lịch sử từ các nguồn trong `HISTORY_SOURCES`: **Wayback** (`wayback_301_history`, đọc header 301 gốc — chuẩn nhất nhưng nhiều ISP VN chặn đích danh archive.org ở tầng IP/SNI) + **archive.today** (`archive_today_history`, thử các mirror `ARCHIVE_TODAY_MIRRORS`, vào được khi archive.org bị chặn — nhưng lưu nội dung theo redirect nên chỉ cho link bản lưu, không đọc được 301 gốc). Deploy web (server ngoài VN) thì Wayback chạy bình thường. Thêm nguồn = 1 dòng dict + 1 nhánh trong `redirect_history`. Cả 2 là expander tùy chọn, không bật mặc định. Bên dưới mục "🔎 Tìm domain trỏ 301 về đây": có **ô chọn nguồn NGAY tại chỗ** (Gộp / SE Ranking / DataForSEO — chỉ hiện nguồn đã có key, mặc định Gộp), gọi `provider.redirect_sources(domain, limit)` quét index rồi hiện bảng ĐƠN GIẢN theo domain (Trang gốc → Redirect đến → Trạng thái → Ngày → Nguồn), metric: tổng redirect / đang trỏ / số domain gốc. **Đa nguồn bắt buộc** (xem memory multi-source-api): 1 nguồn → lệch/thiếu (SE Ranking `/history` là nhật ký sự kiện, bỏ sót redirect ổn định); Gộp cộng nhiều index. Không index thì không liệt kê được (giới hạn bản chất). Cột `Khớp`/phân-nhóm-URL trong providers.py vẫn tính nhưng KHÔNG hiển thị (user chỉ cần mức domain).
  - Tab 3 "Phân tích Backlink (API)" — phân tích THEO TIER: tier 1 = backlink trỏ về target; tier 2/3 = backlink trỏ về các trang nguồn của tier trước. `pick_expand_sources()` chọn N trang rank cao nhất (mỗi domain 1 trang, loại domain đích, chống query trùng bằng set `queried`), dedupe backlink toàn cục bằng `seen_pairs`. Mở rộng tier chạy song song (ThreadPoolExecutor, tối đa 5 luồng), lỗi từng nguồn ghi vào `warnings` chứ không dừng cả lượt. Xuất Excel: Tổng quan, Anchor, Tier 1/2/3, Gộp.
  - Tab 4 "Lịch sử (24h)" — `save_history/list_history/load_history_sheets/clear_history` ghi mỗi lần chạy vào SQLite `history.db` (cột: ts, kind, label, sheets=JSON các DataFrame). Mọi hàm bọc try rộng (lỗi lịch sử KHÔNG được phá luồng chính); mỗi lần đọc/ghi tự `DELETE WHERE ts < now-24h`. 3 tab kia gọi `save_history(...)` sau khi có kết quả.
  - `run_parallel(...)` — ThreadPoolExecutor + progress bar, số luồng là ô nhập số trong từng tab.
  - **Deploy web + mô hình key (C, linh hoạt)**: `get_secret()` đọc env → `st.secrets`. `is_multi_user()` = có `MULTI_USER=1`. Khi multi-user: key user nhập chỉ lưu `st.session_state["user_cfg"]` (KHÔNG ghi config.json), `load_config()` ưu tiên session rồi fallback `_owner_config()` (key chung của chủ qua Secrets); `config_for_display()` CHỈ hiện key trong phiên (không lộ key chủ cho người khác); `save_config()` ghi session thay vì file. Local: `load_config`/`save_config` dùng config.json như cũ (+ env override). `APP_PASSWORD` bật màn hình đăng nhập (session_state auth_ok). `Procfile` chạy `streamlit run` với `$PORT`. Streamlit KHÔNG chạy Vercel/Netlify (chỉ tĩnh) — dùng Streamlit Cloud/Railway/Render. **BẮT BUỘC MULTI_USER=1 khi chia sẻ nhiều người** kẻo key 1 người ghi vào config.json chung lộ sang người khác.
- `providers.py` — adapter API, TÁCH RỜI khỏi luồng check thủ công:
  - `DataForSEOProvider(login, password)` — Basic Auth, POST `/v3/backlinks/{summary|backlinks|anchors|referring_domains}/live`, parse 2 lớp `status_code` (20000 = OK).
  - `SERankingProvider(keys)` — header `Authorization: Token <key>`, GET `/v1/backlinks/{summary|all|anchors|refdomains}`; **xoay key tự động**: HTTP 401/402/403 → đánh dấu key lỗi trong `key_log`, chuyển key kế tiếp; hết sạch key thì raise `ProviderError`. **HTTP 429 KHÔNG xoay key** — là rate limit tạm thời: tự giãn nhịp (`_wait_slot`, tối thiểu 1.5s giữa 2 request kể cả đa luồng) + backoff thử lại cùng key tối đa 5 lần, quá 5 lần mới coi là key hỏng. Thread-safe (threading.Lock quanh chỉ số key + throttle) vì tier 2/3 gọi song song.
  - **Đã xác nhận bằng key thật (2026-07-23)**: summary trả `{"summary": [{...}]}` (phải mở lớp bọc); backlinks trả `{"backlinks": [...]}`; anchors trả `{"anchors": [...]}`; field khớp mapping. `inlink_rank` của trang thường = 0 nên `pick_expand_sources` sort theo (rank trang, rank domain).
  - `redirect_sources(url, limit)` — tìm trang gốc trỏ 301 về `url`, **QUÉT RỘNG toàn domain** (`domain_of(url)`) rồi phân nhóm bằng `classify_match()` (so `_exact_url_key`/`_norm_url_key`: bỏ scheme/www/'/'-cuối, NORM bỏ thêm query) → cột `Khớp` = MATCH_EXACT/NORM/CHAIN/OTHER; `sort_redirect_rows()` đưa nhóm khớp + link sống lên đầu. SE Ranking: GET `/history` `mode=domain, link_type=redirect, date_from=2000-01-01` (bọc `new_lost_backlinks`; dùng `redirect_chain_urls` để bắt CHAIN). DataForSEO: POST `/backlinks/live` `mode=domain` + `filters:["item_type","=","redirect"]`, đích cuối `url_to_redirect_target`. Dedupe theo cặp (url_from, url_to).
  - `AggregateProvider(providers)` — nguồn "Gộp": `_fanout()` chạy mỗi method trên tất cả nguồn con song song (ThreadPool), 1 nguồn lỗi → ghi `notes` + tiếp tục, CHỈ raise khi tất cả lỗi. Gộp backlink/redirect loại trùng bằng `_exact_url_key`, gắn cột "Nguồn"; summary/anchor gắn tên nguồn vào nhãn. `key_log`/`notes` gộp từ các nguồn con. `build_provider("Gộp",...)` tạo cả 2 provider con, thiếu key 1 bên thì bỏ qua bên đó + note.
  - Cả 2 trả dữ liệu đã chuẩn hóa (cột tiếng Việt) — thêm provider mới chỉ cần class cùng interface + nhánh trong `build_provider()`.
- `config.json` — provider đang chọn + credentials, do UI ghi (nút "Lưu cấu hình"), KHÔNG commit/chia sẻ file này.
- `run.bat` — end-user double-click để chạy (tự cài requirements).
